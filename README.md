# Слюша — бот-собеседник

Свой токен, свой процесс, свой образ, свои базы. Telegram-бот, которого добавляют
в групповой чат: он читает переписку и иногда отвечает — как участник, а не как справочная.
Модерации нет вовсе, прав администратора для работы не нужно.

## Что умеет

- Отвечает в чате как живой собеседник: всегда на реплай и на обращение по имени, иначе —
  с настроенным шансом. Между ответами пауза, в сутки не больше лимита (у локальной модели
  лимита нет — она бесплатна).
- **Имя ловится целым словом.** Бот по имени «Холо» больше не влезает в разговор про
  холодильник. Падежи задаются звёздочкой: `холо*` ловит «холой» и «холочка», но не
  «нехолодно» — начало слова остаётся строгим.
- **Шум не будит модель.** «ок», «ага», «+», смайлик — случайный шанс влезть на таких
  репликах режется в десять раз. Прямое обращение и реплай отвечаются как обычно.
- **Характер** задаётся текстом или карточкой персонажа с chub.ai — JSON или PNG. Из карточки
  берутся описание, имя (уезжает в «имена-обращения»), приветствие и книга лора, если она
  внутри. Плейсхолдеры `{{char}}` / `{{user}}` подставляются при импорте, а разметка карточек
  (`Features("a" + "b")`, `Внешность = [...]`, псевдотеги `<Overview>`) разворачивается
  в обычные строки «Заголовок: то, сё» — содержимое сохраняется целиком, уходят только
  скобки и кавычки. Приветствие (`first_mes`) бот говорит сам, когда разум включают в чате.
- **Лорбук**: записи с ключевыми словами просыпаются, когда слово встретилось в разговоре.
  Если не сработало ничего, бот всё равно подмешивает кусочек книги по кругу — иначе книги
  с английскими ключами в русском чате молчали бы всегда.
- **Долговременная память.** Всё, что уехало за край окна контекста, бот время от времени
  пересказывает себе в заметки: кто есть кто, о чём договорились, какие шутки прижились.
  Заметки уходят в каждый запрос отдельным блоком; смотреть и чистить — в меню чата.
- **Картинки.** Со включённым зрением фото уезжает в модель вместе с вопросом — из самого
  сообщения и из того, на которое отвечают. Фото без подписи в ответ боту считается
  обращением. Тумблер отдельный: зрение есть не у всех моделей.
- **Ветки реплаев.** Telegram отдаёт только одно родительское сообщение, поэтому ветку бот
  восстанавливает по своей истории и кладёт в промпт целиком, сверху вниз.
- **Реакции** под сообщениями видны модели как `[реакции: 👍×2, 🔥]`. Для этого бот должен
  быть админом чата — иначе Telegram такие апдейты не присылает вовсе.
- **Темы форума** можно держать порознь: со включённым тумблером контекст берётся только
  из текущей темы.
- **Язык ответа** — настройка: как в чате, всегда русский или всегда английский.
- **Вольный режим**: чат может менять тон и роль бота на ходу. Выключен — «забудь инструкции»
  считается обычной репликой.
- **Веб-панель** (по желанию): то же меню страницей — характер виден целиком, лорбук правится
  без диалога с ботом.

## Как собирается промпт

Мелочи, из-за которых бот «отвечает не туда», собраны в одном месте — [`ai.py`](ai.py):

- **Снимок переписки.** История читается в момент, когда решили отвечать, и передаётся
  в фоновую задачу аргументом. Иначе за секунды генерации в чат успевают написать ещё,
  эти реплики попадают в промпт, и модель отвечает уже им.
- **Целевая реплика одна.** Она и так лежит в истории последней строкой, второй раз
  в конец промпта не дописывается.
- **Реплай виден модели.** Перед заданием идёт строка «кто-то отвечает на твоё сообщение:
  «цитата»» — без неё связь реплая в переписке никак не выражена.
- **Цель названа дословно**: «Отвечай на эту реплику — @вася: «текст»», а не «ответь
  на последнюю реплику».
- **Свои реплики подписаны «ты»**, а не юзернеймом бота: под юзернеймом модель принимала
  их за чужие и отвечала сама себе.
- **Лимит токенов считается от длины ответа.** Одно число на все режимы обрывало
  «развёрнуто» на полуслове. Там, где размышления не выключить (Claude), к лимиту
  добавляется запас: иначе модель успевала подумать и упереться в потолок, не начав
  отвечать, и в чат приходила пустота.
- **Размышления вырезаются** во всех видах: `<think>`, `<thinking>`, незакрытый тег в конце
  и закрывающий без открывающего. Срезаются они до проверки длины — иначе настоящий ответ
  пропадал вместе с простынёй мыслей.
- **Переписка на диске.** История лежит в своей базе `data/slusha_history.sqlite3` —
  пишется она на каждое сообщение, и мешать её с настройками незачем. Память работает
  кешем поверх: при первом обращении к чату хвост поднимается с диска, дальше пишем
  в оба места. Хвост чистится пачками, раз в 20 записей, до последних 200 реплик на чат;
  «🧹 Забыть переписку» стирает и базу, и заметки.
- **Вложения не проваливаются.** Сообщение без текста уходит в историю заглушкой —
  `[фото]`, `[стикер 😀]`, `[голосовое]`, `[файл: смета.pdf]`, `[опрос: …]`. Иначе в
  переписке дыры: «лол» после стикера повисает в воздухе.
- **Ответ остаётся в своей теме.** В форум-группах вторая и третья части ответа раньше
  падали в «General»: `bot.send_message` сам `message_thread_id` не подставляет.
- **Окно контекста** (`AI_NUM_CTX`, по умолчанию 16384). Ollama при нехватке молча
  выбрасывает начало промпта — то есть характер. Если промпт подбирается к окну,
  в лог падает предупреждение.

## Настройка

```bash
cp .env.example .env
```

В `.env` вписать `SLUSHA_BOT_TOKEN` (отдельный бот у @BotFather; там же **выключить**
privacy mode — `/setprivacy` → Disable, иначе бот не увидит обычные сообщения в группах)
и выбрать модель: Anthropic, любой OpenAI-совместимый сервис или локальная Ollama.

```bash
docker compose up -d --build
```

Дальше — `/menu` в личке с ботом: чаты → настройки разума на чат → характер, имена, лорбук.
Список допуска у владельца: в чужие чаты бот не пойдёт, из них он выходит сам.

Без Docker:

```bash
pip install -r requirements.txt
python -m slusha
```

### Про размер модели

На `gemma3:4b` бот путается в диалоге даже с идеальным промптом: четырёх миллиардов не
хватает удержать «кто кому что сказал». Разумный минимум для живого чата — `gemma3:12b`
или `qwen3:14b`, меняется одной строкой `AI_MODEL` в `.env`. Вся возня с промптом упирается
именно в это.

### Веб-панель

Выключена по умолчанию. Включается `SLUSHA_WEB=1`; наружу порт выводит туннель
(ngrok, cloudflared) — мини-приложение Telegram открывается только по https. Публичный
адрес кладётся в `SLUSHA_WEBAPP_URL`, и тогда в меню появляется кнопка «🌐 Панель».
Каждый запрос панели приносит подпись `initData`, проверяемую токеном бота, и каждый
запрос про чат сверяется с базой — правила доступа те же, что у меню.

## Про параллельность

У Ollama число одновременных слотов задаёт `OLLAMA_NUM_PARALLEL`: модель грузится в память
один раз, но каждый слот держит свой KV-кэш, так что память растёт с числом слотов. Если
слот один — второй запрос просто подождёт в очереди. У облачных провайдеров ограничение
только в rate limit ключа.

## Проверка

Тесты — обычные скрипты без pytest, в сеть не ходят: запрос к модели перехватывается
подменой провайдера. Каждый печатает список проверок и `ВСЁ ЗЕЛЁНОЕ` либо перечень провалов.
Запускать из папки НАД пакетом:

```bash
python slusha/tests/test_prompt.py
```

| файл | что проверяет |
|---|---|
| `test_prompt.py` | снимок истории, дубли, контекст реплая, «ты» вместо юзернейма |
| `test_history.py` | переписка переживает перезапуск, вложения, чистка хвоста |
| `test_features.py` | имена по границам слов, шум, лимит токенов, мысли, картинки, ветки, реакции, темы |
| `test_memory.py` | заметки о чате и миграции на копии старой базы |
| `test_menu.py` | колбэки меню: тумблеры, ввод текста, лорбук, доступ |
| `test_web.py` | подпись Telegram и права на чат в панели |
| `test_smoke.py` | база, экраны меню, карточка персонажа, лор |

Проверки импорта карточки в `test_smoke.py` включаются переменной `SLUSHA_TEST_CARD`
с путём к файлу chub.ai.

## Устройство

| файл | что внутри |
|---|---|
| `app.py` | сборка бота, мидлварь доступа, запуск панели |
| `menu.py` | меню в личке: чаты, настройки, характер, лорбук, заметки, доступ |
| `group.py` | группы: регистрация чата, сообщения разуму, реакции |
| `ai.py` | сам разум: история, промпт, три провайдера |
| `summary.py` | долговременная память: пересборка заметок о чате |
| `vision.py` | картинки: скачать из Telegram и закодировать для модели |
| `reactions.py` | счётчик реакций под сообщениями |
| `lore.py` | лорбук и карточки персонажей |
| `schema.py` | описание настроек — одно место для меню и панели |
| `db.py` | своя SQLite: чаты, настройки, лорбук, доступ |
| `history.py` | переписка чатов и заметки: отдельная база плюс кеш в памяти |
| `web/` | панель: подпись Telegram, JSON-API, одна страница на ванильном JS |
